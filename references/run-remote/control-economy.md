# Remote action control economy

Load this reference only for a remote mutation, custody action, storage recovery, or teardown. It turns safety
into a short consequence-specific decision instead of a controller project.

## One outcome, one action surface

Read-only diagnosis, offline preparation, and same-scope repair of an unexecuted action continue under the
already authorized bounded outcome. The first remote mutation uses one executable action decision, validated by
the executor before its first side effect, then one thin receipt and one independent postcheck. Never add a
generic proof framework, unrelated scanner, or nested authorization package around a maintained primitive.

Use one initial package plus one successor as the complete control budget. Assembly, formatting, parser, reviewer,
wrapper, transport, and other no-science-side-effect failures all count. A third version is forbidden; renaming
the action does not reset it. Preserve failed evidence by pointer/hash, repair the maintained primitive, use a
minimal operator-visible command, or report one blocker.

Routine probe/launch/pull/shutdown defaults: at most 8 managed control files, 500 new executable lines, and a
64 KiB receipt excluding linked logs/manifests. Keep receipts thin. A receipt stores decision, target/source
identities, result, and pointers/hashes—not scripts, full rosters, or captured output. Do not embed controllers,
full rosters, or logs. Immutability applies to the receipt, not cloned scaffolding.

Do not apply the control-package budget to scientific identities. When a protocol-preserving bug is inside
frozen content-addressed source, never patch the frozen source or bypass its identity check. Create one minimal
scientific source successor bound to its exact plan, prove the change through the real consumer, and write a
fresh run/output identity. That is not a renamed action-gate Vn and does not justify more wrappers or reviewers.

## Exact consumer regression

Before freeze or execution, run producer -> serializer -> consumer/parser -> runner -> target shell/OS with real
schema, paths, quoting, UTC representation, directory ancestry, owner/mode checks, and exit propagation. Mocks
may suppress network or billable side effects but must not replace the real parser or runner. After one remote
failure before science, isolate that root cause and test the exact chain; do not expand the framework.

## Capacity and storage recovery

**Capacity is a threshold, not an equality invariant.** Bind device identity, non-overwrite target, required bytes and safety margin.
Space drift from logs or temporary files is normal. Never require two
`available_bytes` readings to match; fail only on device change, query incompleteness, target/writer conflict, or
capacity falling below the frozen floor.

At >=90% byte/inode use, stop new writers and run the storage-pressure recovery ladder:

1. resolve the actual mount and inventory largest paths/live writers;
2. protect active, unknown, checkpoint, result, and paper-bearing data;
3. reclaim only proven-regenerable task-local cache/temp/failed staging under an exact allowlist, after no-writer
   and reclaim-size checks, with a compact receipt;
4. mirror valuable portable artifacts to a fresh private prefix when that advances the outcome; require exact
   roster/bytes/hash, independent restore, and semantic load before cleanup eligibility;
5. remeasure `required + margin`; if still short, report exact shortfall, recommended expansion, and restart
   requirement rather than minting gates or shrinking science.

Resolve provider storage aliases before judging them. A provider-owned symlink's conventional mode `0777` says nothing about its target.
Bind alias owner and link text, resolve stable ancestry, validate canonical target device,
inode, mount id, source/fstype, capacity, writer state, and a fresh `O_EXCL` child; execute against the bound canonical path.
Reject mutable/untrusted resolution, not the mere alias.

## Observational probes and executor identity

Prove that read-only probes are observational. Some tools create default state while checking it; invoking Screen with
an absent `SCREENDIR` can create or touch the directory. If the missing namespace already proves absence, do not invoke
the utility. Break-test pre-side-effect probes on absent paths and require entry/byte/
metadata equality before and after.

A remote preflight must not reject its own control connection. Bind the exact executor ancestry from
PID/PPID/starttime/session/cmdline and exclude only that chain from other-session checks; never use grep/substrings
or exclude every `sshd`. Expected unreadable `exe`/`cwd` for the bound privilege-separation ancestor is not global query incompleteness
if alternate proc fields close identity. Any extra SSH session,
unbound denial, or ancestry gap still blocks.

Postcheck the identity that actually ran: consumed target, session/socket, launch identity, current process argv,
and artifacts. If transport or local receipt capture fails after dispatch, never infer remote failure or retry;
enumerate the exact live namespaces/processes/markers first. A local capture defect does not erase remote truth,
and checking the wrong session/path cannot support `NOT_RUNNING`.

## Producer cardinality

Reconcile artifact cardinality at the producer boundary. Derive budgets from the actual multiplicity per accepted record
and declared roles. If a contract promises `N` records and exactly `N` task-native PNGs, each
record publishes one counted task-native PNG. Any extra convenience artifact needs its own role/path/count.
Do not raise a budget to hide a producer/contract mismatch; test one record and the `N`/`N+1` boundary through
the real producer.

## Custody, shutdown, and release

Do not confuse release-readiness with release authority. “Safe enough that release would lose nothing” is a
custody acceptance criterion, not permission to destroy. If the latest decision is “shut down, do not release,”
complete exact canonical-remote restore and independent-consumer semantic acceptance, run the normal shutdown preflight,
shut down once, verify offline, and preserve the provider disks.

Retire provisional prohibitions. `No release until independent consumer verification` is a state guard, not a permanent `never release`.
When exact custody closes the protected risk and the current user authorizes release,
bind the instance and execute the shortest supported release path with one disappearance/billing postcheck.
Release, shutdown, evidence deletion, cache cleanup, overwrite, and non-overwriting repair are distinct
consequences.

Before destructive teardown, prove that every reported result re-reads from an independently restored temporary
consumer copy. Exact roster, bytes/SHA-256, safe loads, and full-prediction semantic re-derivation establish
custody; they do not mint authority. The consumer may be remote; a local `PULL_VERIFIED.json` is only one
materialized-local delivery receipt.

## Topology and user-visible notice

Preflight topology before moving bulk data. For work above 1 GiB or 15 minutes, record source, destination,
required residency, independent failure domain,
and purpose. Two drive letters on one physical device are not independent restore evidence. Do not move a large
payload through the local claim plane when remote-to-remote validation satisfies the stated outcome.

Give one zero-surprise action summary in a plain-language message before material work: result, exact action and
target, expected data/time/cost, destination, reversibility, and stop condition. This does not reopen already matching authority.
Afterward, a durable event-driven monitoring mechanism owns cheap heartbeats without waking a model; wake the model
and report only a material delta, terminal state, blocker, or new decision.
